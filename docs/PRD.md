# 本地指纹浏览器产品需求

版本：1.0 · 日期：2026-09-30 · 目标系统：Windows 桌面

本项目帮助电商使用者在一台 Windows 电脑上管理多个长期使用的浏览器环境。每个环境拥有独立浏览数据、固定设备档案、独立代理配置和固定内核版本，能够在关闭、重启及备份恢复后继续使用。

**原始交付为React/TypeScript原型与文档；T01–T04的本地配置、安装器与精确内核已经验收。** 独立网页原型仍在localStorage保存演示数据，启停/代理/内核为示例，不会启动fingerprint-chromium。原型JSON不包含真实浏览数据，也不能导入原生工作区。桌面T05固定档案/T06正常会话/T07异常监督已本地实现待验收；目前只有用户明确确认的直连策略进入运行实现，已绑定代理必须阻断，未接入功能不回退模拟。按用户先开发的要求暂不执行CI和完整回归，不把源码或旧证据算成新功能通过。完整要求分票交付，实际验收见 [当前进度](PROGRESS.md) 与 [记录](ACCEPTANCE.md)。

## 2 核心工作流程

1. 在代理页批量导入代理，预览格式与错误，再保存。原型只展示明确标记的示例检测结果。
2. 在内核页选定已安装的固定版本；桌面版验证实际可执行文件及校验值。
3. 在环境列表创建环境：填写名称，绑定代理和内核，生成一套设备档案并保存。
4. 按需导入 Cookie；先看解析数量、目标域名和错误，再确认写入指定环境。
5. 启动环境。桌面版先检查配置、数据锁、内核和代理，成功后打开独立浏览器窗口。
6. 关闭后保留浏览数据；下一次使用同一档案、同一内核和同一数据目录。
7. 定期导出本软件备份。恢复前查看影响范围；恢复完成后验证环境身份、代理绑定、内核和浏览数据。

## 4 功能规格

以下定义完整产品目标。当前原型只验收上一节列出的范围，以及第 7 节“原型验收”列；桌面专属能力须在后续阶段实施和测试。

### ENV-001 环境列表与批量操作

环境列表展示名称、分组或标签、代理、固定内核、设备档案摘要、运行状态和最近操作。提供名称/备注搜索，以及状态、代理和标签筛选。筛选结果为空时给出清除筛选入口；首次无环境时给出新建入口。

选择框只操作当前明确选中的 ID，筛选改变不能悄悄扩大操作范围。批量启动、停止、复制和删除均显示数量与逐项结果。一个环境失败不应把其他环境的成功结果改成失败；取消批次后保留已经完成的项目，并准确列出尚未执行的项目。

批量创建接受正整数数量及名称前缀，以分批任务处理大数量请求。没有产品级最大实例数；资源不足时显示具体原因和已完成数量，允许继续或重试。重复点击提交不能重复创建同一批次。

### ENV-002 创建与编辑环境

右侧抽屉使用三个页签：

| 页签 | 字段和行为                                                                                |
| ---- | ----------------------------------------------------------------------------------------- |
| 基础 | 名称、分组/标签、备注、代理、内核；新建可选择数量和命名规则。                             |
| 指纹 | 设备模板、seed、Windows 平台、语言/时区、CPU 档位、窗口偏好、能力状态；提供“生成新档案”。 |
| 偏好 | 启动网址、会话恢复偏好、窗口大小，以及代理失败时停止的说明。                              |

名称不能为空且在当前工作区保持唯一，内部仍通过不可变 ID 区分。启动网址限有效 HTTP/HTTPS URL；原型不支持 `about:blank` 输入。代理和内核引用必须有效；删除被引用对象时不得静默清空环境绑定。

修改名称、标签和备注可以在运行时保存。影响指纹、代理、内核和数据目录的修改必须在停止状态执行。运行时打开编辑仍能查看相关字段，但说明“停止后可修改”。取消抽屉不保存未提交修改；关闭存在未保存内容的抽屉时提供保留编辑或放弃的选择。

“复制为新环境”复制配置模板并保留原代理绑定，新建 ID、独立空数据目录、新 seed；不默认复制登录状态。原型会在创建抽屉中展示继承的代理，用户可以修改；复制不代表自动分配一个新的公网 IP。恢复备份属于恢复原身份，不能复用新建复制逻辑。

### ENV-003 启动停止与失败保护

桌面版启动顺序固定为：校验配置 → 获取数据目录独占锁 → 核验固定内核 → 建立代理通道与实际出口检查 → 生成启动参数 → 启动进程 → 等待就绪 → 打开启动页面。每一步可定位错误，失败后释放本次取得的锁和临时资源。

同一环境重复点击启动，只返回现有启动任务或聚焦已有窗口。停止优先正常关闭，超时后允许用户结束该环境进程；不能仅按进程名结束所有 Chromium。进程意外退出时记录错误并保留数据。

应用重开时核对原PID的创建时间、会话身份和实际目录锁；未确认退出仍保护关键配置和数据，不能把保存的running或无PID记录直接当已停止。当前私有通道不能跨应用重建，待核对会话需正常关闭原窗口后再核对，不能按旧PID强行接管。只有仍由当前监督器控制的准确会话、普通关闭已经失败时才提供明确确认的强制结束；活动里的旧会话不能控制后来新开的浏览器。见[运行术语](../GLOSSARY.md)与[T07边界](verification/T07.md)。

已配置代理不可用时停止启动；运行中代理断开后保持代理配置、阻止未经该代理的网络出口，并提示故障。重连成功后允许继续使用同一环境。是否真的没有直连回退需要桌面网络测试验证，不能由 UI 状态推断。

原型点击启动/停止只改变演示状态，界面持续显示示例模式。示例失败必须显示失败原因与可恢复操作，不能出现“代理已真实验证”或“真实浏览器运行中”的措辞。

### FP-001 一次生成并持久化设备档案

设备档案在首次保存时生成，至少保存 `seed`、模板版本、生成器版本、目标平台、语言、时区、CPU 参数、能力版本以及已选内核标识。seed 必须显式写入数据，不能只靠环境 ID 计算；这样恢复时即使内部 ID 需要映射，也能保留原身份。

生成规则：

1. 从 Windows 桌面模板开始，不随意混入 macOS、Linux、手机字段。
2. 根据已选内核版本确定品牌及版本映射；UA、UA-CH 等相关字段作为一组处理。
3. 地区、语言和时区成套生成。代理地区可作为建议，用户确认保存后冻结，不在每次启动时自动改写。
4. CPU、窗口和可支持的硬件字段从有版本的合理模板集合选择；不能把每个字段彼此独立随机。
5. 生成正整数 seed，持久保存；不同环境的新档案检查 seed 冲突，但不把 seed 不同等同于所有指纹必然不同。
6. 将模板展开为配置，通过能力适配器生成当前内核支持的参数；无效字段留在报告中，不能伪装成已生效。

窗口宽高是窗口偏好，不能命名为“屏幕指纹已修改”。Canvas、Audio 等噪声的真实实现由选定内核负责，管理端不编造额外算法能力。

“重新生成”只在停止状态可用，并明确提示将改变设备档案。保留旧档案版本用于回滚；重新生成不应自动删除 Cookie 或其他浏览数据。

### FP-002 指纹能力分层

每个字段均属于以下一种状态，UI 使用文字说明，不能只靠颜色：

| 状态             | 含义                                         | 操作方式                     |
| ---------------- | -------------------------------------------- | ---------------------------- |
| 直接可配置       | 固定内核支持独立参数，且本项目完成对应验证   | 允许编辑，保存实际值。       |
| 内核按 seed 生成 | 修改结果由内核实现，管理端只能给 seed 或开关 | 展示来源，不提供假精细参数。 |
| 跟随真实环境     | 使用当前系统或内核原生值                     | 展示只读说明。               |
| 不支持或未验证   | 当前版本无相应能力，或尚无验证证据           | 禁用编辑，说明原因。         |

能力表按“内核版本＋平台＋适配器版本”记录。原型展示设计状态，不能把它当作本机运行验证结果。升级内核后必须重新评估受影响字段，不能沿用旧版本的有效标记。

### PRX-001 代理导入检测与分配

支持 HTTP、HTTPS、SOCKS5 及用户名密码认证。第一版文本输入支持代理 URI 和有格式说明的 `host:port:username:password`；IPv6 和包含分隔符的密码使用 URI，用户名密码按 URI 规则编码。不得用简单的全量冒号切分误解析 IPv6。

导入分为“粘贴或选择文件 → 逐行解析预览 → 确认保存”。预览包括协议、地址、端口、认证是否存在、错误行及重复候选。允许有效行保存，错误行保持可复制修正；不得悄悄丢弃。密码默认遮罩，不进入列表、活动记录或导出日志。

代理是可复用对象，每个环境独立绑定。独立配置不保证代理供应商提供独立公网 IP；多个环境绑定同一代理或检测到相同出口时提示，但不硬性禁止。批量分配显示环境与代理对应关系，不能无提示用轮询方式重复代理。

桌面检测区分格式校验、连接、认证、目标访问及出口信息；记录检测时间。上一次检测成功不保证下次启动成功，因此启动仍需检查。原型检测不发起真实网络请求，结果标记“示例”。

### CK-001 Cookie 导入

从环境行进入 Cookie 对话框，始终显示目标环境名称和 ID。接受 JSON Cookie 数组及 Netscape 文本；标准请求头 Cookie 缺少域名等信息，不作为无需补充即可导入的完整格式。导入前展示总数、有效条数、过期条数、错误条数、域名分布和冲突数量。

同名 Cookie 按 name、domain、path 及受支持的 partitionKey 共同识别。默认合并并替换完全相同键的 Cookie；全量清空后导入必须由用户明确选择。空字符串 value 是合法输入，不能按空值过滤；session Cookie 不凭空补一年的有效期；过期 Cookie 提示跳过或保留为解析结果，不擅自续期。

保持 secure、httpOnly、sameSite、path、expires 等语义；保留能被固定内核正确支持的分区信息，遇到不支持字段应报告而非静默移除。解析成功与写入成功是不同结果。桌面版通过指定环境的 CDP 写入，并读取核对，逐条报告失败；写入失败不能返回整体成功。Cookie 导入不会替代 LocalStorage、IndexedDB 等其他网站数据，也不承诺只导入 Cookie 就能恢复所有登录。

原型已支持 JSON 和 Netscape，解析并保存示例 Cookie 对象及其值，用于演示合并和快照恢复，不写真实浏览器。预览标注已过期的解析记录；保存仍保留其原始过期时间作为样例，不续期，也不表示真实浏览器会接受这些 Cookie。示例值会进入当前浏览器的 localStorage 和演示快照，因此不要填入真实账号 Cookie；生产实现不把完整 Cookie 值写入活动日志。

### CORE-001 固定内核版本

内核记录包含项目来源、精确版本、Windows 架构、归档及主程序校验值、安装路径、安装状态和能力表版本。多个环境可复用同一只读内核，浏览数据分别保存。

新建时解析并保存实际内核 ID，不仅保存“跟随默认”。默认内核变动只影响后续新建环境。缺失或损坏时阻断启动，不自动换版本。被使用或正在运行的内核不可直接删除；提供受影响环境清单。

升级流程是安装新版本 → 用测试环境验证 → 用户选择环境迁移 → 保留旧版本和迁移前备份。浏览数据被新版本写入后，不承诺可以直接降级打开。原型只演示版本选择和元数据管理，不下载或验证真实内核。

### BKP-001 本软件备份与恢复

两种交付形态必须在名称、格式及导入校验中区分：

| 形态     | 当前原型                                                                                    | 未来桌面版                                                                                       |
| -------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 文件含义 | 演示数据 JSON 快照                                                                          | 本软件配置和实际浏览数据备份包                                                                   |
| 包含范围 | 演示环境及示例 Cookie、设备档案、代理和内核元数据；导出时排除代理密码                       | 配置数据库快照、设备档案、代理绑定及受保护凭据、每实例 user-data-dir、内核版本清单、文件校验清单 |
| 不包含   | Chromium 程序、真实 Cookie 数据库、真实浏览历史、系统凭据、代理密码、历史快照列表和活动列表 | 系统级设置；内核本体是否随包携带由备份选项明确，未携带时恢复必须找到同版本同校验值的内核         |
| 成功含义 | 原型可读回且相关页面数据一致                                                                | 数据完整、引用一致、身份不变，并通过真实重开验证                                                 |

桌面版支持全量及选定环境备份；原型仅创建全工作区快照。桌面版备份前停止相关环境并完成数据库一致性快照；停止失败则中止，不把仍在变化的数据打包后标记完整。包清单带 schemaVersion、appVersion、生成时间、各环境 ID、明确 seed、内核版本和文件摘要。

恢复必须先校验格式、schema、文件路径和摘要，再展示新建、覆盖及冲突影响。恢复原环境保留原设备档案；“另存新环境”须明确是否保留原身份，不能与新建独立环境混淆。首版本地恢复可统一使用“替换当前演示数据”或明确的桌面覆盖流程，不做第三方包格式兼容。

桌面版先恢复到同卷暂存目录，验证后进入维护锁，保留旧数据为回滚副本，再切换目录和数据库引用。任何一步失败可恢复旧状态；只有全部必需组件完成才报告“恢复完成”。部分失败必须显示“恢复未完成”，禁止用通用绿色成功提示掩盖缺失模块。文件系统与 SQLite 不具有共同事务，具体操作日志与崩溃恢复见 [开发方案](DEVELOPMENT.md#9-备份和恢复的一致性)。

原型快照标识为 `format: "prism-prototype"`、`schemaVersion: 1`，包含 environments、proxies、kernels 数组。文件先校验再展示恢复确认；无效文件不能破坏已有演示数据。恢复要求先停止所有模拟运行环境；恢复后环境为 ready（已停止/待启动），代理密码清空且状态重置为 unchecked，需重新填写演示凭据并检查。历史快照和活动列表不从文件覆盖。存储写入失败时仍可能存在内存与磁盘差异，生产级持久化原子性属于后续桌面要求。

### DATA-001 数据隔离与删除

环境 ID 不变，数据目录由程序管理，禁止多个环境指向同一目录。目录解析校验必须约束在软件数据根目录内；不能仅拼接用户输入。运行时持有独占锁，其他进程不得同时使用该数据目录。

删除前显示环境数量、是否包含浏览数据、是否存在备份。运行中的环境先停止；停止失败不删除。桌面版先移入本地回收区并记录恢复信息，用户在回收区明确操作后才永久删除；目录移动前检查路径及重解析点。原型删除只影响其演示数据，并提供明确确认，不得使用真实文件删除能力。

### UX-001 可访问性和本地持久演示

主操作不藏在多层菜单中；状态用文字和颜色共同表达。表单具有标签、错误提示及合理的默认值。抽屉和对话框支持键盘操作、Escape 关闭、焦点约束及关闭后回到触发按钮。删除、重新生成档案、替换恢复分别有清楚的影响说明。

原型刷新后保留已保存的环境、代理及设置；未提交草稿不持久化，关闭有未保存修改的环境抽屉会确认是否放弃。T01 应用契约使创建编辑在存储成功后才显示完成；存储不足保留旧状态和可重试草稿，明确提示本次未保存。这不是 SQLite/目录共同恢复能力。

检测到损坏 localStorage 时保留原始内容，阻断工作区操作，提供“导出原始记录”和用户明确选择的“重置演示工作区”，不自动覆盖坏记录。另一个标签页修改相同工作区时，当前页面阻断操作并要求重新载入，避免以过期状态覆盖新数据。此保护不等同于桌面事务修复或合并编辑；真实桌面版仍需磁盘级数据一致性设计。

加载、空列表、筛选无结果、操作进行中、失败及成功均有状态。缩窄窗口后保持核心操作可达，表格允许横向滚动。批量操作显示进度，避免页面长时间无反馈。

### DOC-001 文档与页面可追踪

页面说明、开发任务和验收记录使用本文件需求 ID。使用说明页链接项目首页、PRD 和开发方案；文档链接相关路由。UI 变化影响业务语义时同步文档，不能让原型演示能力被误读成真实桌面完成情况。

## 5 环境状态机

| 当前状态                | 事件               | 目标状态      | 规则                                                         |
| ----------------------- | ------------------ | ------------- | ------------------------------------------------------------ |
| stopped                 | 请求启动           | checking      | 校验配置、数据锁、内核和代理。                               |
| checking                | 校验成功           | starting      | 保存本次启动任务 ID。                                        |
| checking                | 校验失败           | error         | 释放本次资源，说明失败阶段。                                 |
| starting                | 进程及控制通道就绪 | running       | 记录进程身份，不只检查 PID 数字。                            |
| starting                | 超时或进程退出     | error         | 清理本次进程和锁，保留档案。                                 |
| running                 | 请求停止           | stopping      | 正常关闭，等待真实退出。                                     |
| running                 | 代理通道故障       | network_error | 保持代理策略并阻断非预期出口。                               |
| network_error           | 代理恢复且检查通过 | running       | 不更换设备档案。                                             |
| running / network_error | 进程异常退出       | error         | 活动记录保存原因与时间。                                     |
| stopping                | 退出成功           | stopped       | 释放数据锁，允许编辑和备份。                                 |
| stopping                | 超时               | error         | 保留仍存活的进程信息，提供结束进程操作；不得认为目录已释放。 |
| error                   | 问题修复并重试     | checking      | 先确认无遗留进程占用。                                       |

原型实际状态为 ready、starting、running、stopping、error；ready 对应未运行，checking 和 network_error 未拆成独立原型状态。原型不持续监测网络。程序重开后桌面版通过进程身份及目录锁重新核对状态，不直接信任数据库里的 running。
