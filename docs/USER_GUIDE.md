# 棱镜浏览器使用指南

**当前桌面入口（2026-10-07）：** 运行仓库内 `build/bin/prism-browser.exe`，版本 **0.3.0-preview.10**，源码 `95a600f`；不需要启动 Vite。程序来源、SHA-256 及实际验证见[148 多开修复](verification/desktop-148-isolation-fix.md)。当前只使用 **148.0.7778.215**，150 与跨版本迁移不适用；旧失败保留，不算通过。

1. 打开新程序，在环境列表选择已有环境后点“打开”，或点“新建环境”并选择已核验的 148 内核、直连或绑定代理。
2. 代理检查失败时修复代理，再打开**同一个环境**；不用再次创建，不切为直连。普通编辑、关闭和重开保留原 seed、内核与数据目录。
3. 关闭环境及退出程序时等待清理完成；若提示清理尚未确认，按反馈解除占用后重试，不把窗口关闭或退出码本身当作清理证明。

新程序已实际核对直连与两个代理三开、单环境关开不影响其他环境、受控代理故障只停止目标及恢复后原环境重试。两次正常退出均核实自有 Chrome、未闭合网络会话及未释放资源为 0；重启后 204 项配置身份不变，原代理环境真实页面数据读回正确，SQLite 完整性为 `ok`。采用 Ant-Browser 标准共享内核，旧共享 ACL 导致的本机 148 多开 GPU 崩溃触发条件已修复；没有额外 AppContainer/共享 ACL 修改或每会话内核副本，约 425 MiB 副本方案未交付。标准代理方式不承诺系统级全路径强制隔离。

正式 **4/21** 保持，真实自然指纹等待/迟到回复等未证条件仍保留，不表示原 21 项完整收口。用户取消 1:1 要求。下面的源码阶段与旧候选说明保留其历史时点；其中“仅 Vite”“不重建安装包”等描述不是当前新程序的启动方式。

**2026-10-07 使用范围调整：**当前只使用 148 内核。用户要求采用共享浏览器程序、独立环境数据与逐环境代理的方式，取消额外 Windows 容器与权限操作，不为每个环境复制内核。修复及新程序实测状态见[148 多开修复](verification/desktop-148-isolation-fix.md)；以下旧候选的验证不能代替新程序结果。

本文件包含**当前源码UI用法**与**历史首版候选的桌面说明**，不是正式发布承诺。正式验收仍4/21；实现、本机验证、候选包与完整交付分别记录。[首版报告](verification/V1-final.md)记录各候选实际身份和待验项；旧候选二进制不能验证本轮新UI。

## 先看这三点

1. **代理环境始终使用选定代理。** 每次打开先检查代理，失败时提示错误；应用不会自动改为直连，恢复后重开原环境。当前方案不承诺所有网络路径均由 Windows 强制隔离，实际已验证范围见本轮记录。
2. **备份与诊断不是同一种文件。** `.prismbackup` 是包含浏览数据的完整备份；诊断 `.json` 只用于排错，不能恢复环境；网页演示 JSON 也不能导入真实工作区。
3. **候选只用合成数据检查。** 后台回归/真实三存储及硬中断已有结果，人工完整流程、干净Windows和独立远端仍待验；不承诺跨电脑/重装系统保持登录。

## 1 安装、升级与数据位置

Windows 10/11 x64需WebView2，它只承载工作台；真实环境用另行安装的fingerprint-chromium。候选未签名，核对对应release清单与SHA256SUMS后再决定运行，不关闭安全功能。本机实跑仅覆盖Home build26200及148/150，不推导所有Windows组合已获支持。

工作区默认位于 `%LOCALAPPDATA%/PrismBrowser/`，配置为 `app.db`，浏览数据各自独立。正常关闭后升级；卸载默认保留工作区。只有明确选择并再次确认删除全部数据才永久删除。详细步骤见[安装说明](INSTALLATION.md)。

## 2 第一次创建环境

### 当前源码流程（不作为旧候选安装包操作承诺）

1. 从环境列表点“新建环境”。同一窗口填写名称、分组，选择服务提供的可用 fingerprint-chromium 版本，再选“本机网络（直连）”或已有代理。
2. 没有可用内核时按引导打开“内核管理”，准备好后返回继续草稿。native 必须是真实已安装且核验的构建；网页只提供演示版本，不下载或启动产品内核。真实安装仍用固定版本/预期 SHA-256 或明确可信的本地 ZIP，不随意换旧环境版本。
3. 指纹摘要自动准备，不必进入技术页。“换一套”只改草稿身份；不想保存就取消。首次保存后 seed 固定，普通编辑、关闭重开或修改代理都不会自动换身份。
4. 要导入代理，可从窗口点“导入代理”，按原流程解析/保存或取消；返回时原环境草稿仍在。导入成功后选择新代理；取消环境草稿不会撤销已导入的代理记录。
5. 点“创建”只保存，点“创建并打开”先保存再打开。单个操作不需要查看批次计划、配置哈希或内部修订；错误提示仍要处理，不能绕过后台保护。
6. 行内“打开/关闭”用于日常启停；点“编辑”或“更多操作 → 编辑环境”后用“保存”。窗口的基础、代理、常用、指纹四区在同一正文，分区栏只滚动定位；技术详情和档案历史可收起。取消不提交，档案历史回滚仍要预览后明确保存。

阶段合成证据见 [环境表](verification/issue33.md)、[正式环境窗口](screenshots/issue34-integration/README.md) 与 [#36图库](screenshots/issue36/README.md)。每份只证明所标注的提交/状态，最终整组取证另列；截图和浏览器点击不代替真实桌面核验。

代理页和环境窗口共用同一个导入草稿。关闭或切页保留本次内存输入，不自动清除；“清除输入与预览”是独立动作。请求处理中先等待；回执未知时可以隐藏窗口，回来点“核实原导入请求”，不会换一份请求重复保存。导入成功消费已提交行，取消环境草稿不会撤销已保存代理。

CPU、GPU、字体等支持范围以该精确构建能力记录为准。窗口尺寸只是偏好，不等于伪造屏幕指纹。不同 seed 不保证每个输出都不同。

## 3 网络、打开与关闭

代理页支持 HTTP、HTTPS 上游与 SOCKS5 配置、认证和独立检查。凭据使用当前 Windows 用户的本机保护存储。HTTPS 上游指连接代理本身使用 TLS；HTTP/SOCKS5 认证本身不加密。

绑定代理环境启动时创建独立容器与专属桥，检查失败会拒绝启动；当前仅本机受控链路验证通过。启动、停止有独立任务状态；出现“结果待核实”时核对原任务，不把它当成失败后立即重建。资源清理不明时环境继续占用，保留原数据和日志。

当前源码列表明确显示直连/代理和固定版本；打开使用已保存的策略，不反复要求确认内部技术字段。**“已创建，打开失败”不是“创建失败”**：环境已经保留，修复原因后只重试打开原环境，不再点新建、不切直连。创建结果尚未确认时先核实原创建任务；保存失败则继续原草稿，旧记录不变。

分组/搜索用于找到环境，批量按钮只作用于明确勾选的 ID；查看逐项结果，不把一项失败当作全部失败或全部成功。native 运行/待核对/资源未释放时，只能改名称、分组和备注；指纹、代理、内核及启动偏好等关键字段仍受保护。网页 demo 忙环境仍不可编辑。

优先正常关闭。超时、控制通道断开或应用重开后身份未知时，按提示核对准确会话；只有页面明确提供时才强制结束该受控会话。不要凭 PID 或锁文件年龄手工删锁。环境未确认完全退出前不进行目录替换。

## 4 Cookie 与批量操作

Cookie 导入选择明确环境和会话，先粘贴 JSON/Netscape 内容预览，再选定条目。合并与“替换全部”含义不同：后者会先清空该会话的 Cookie，需要明确选择。看实际读回核对数量；未知、失败或过期不能算成功。Cookie 内容不进入诊断。

批量新建/复制/分配冻结所选目标，逐项记录；复制生成新身份和真实空目录，不复制登录数据。取消保留完成项，重试沿原记录。正式FIFO只串行昂贵启动，各入口共用保护；取消等待项不影响其他环境，失败独立重试。调度不是创建/保持运行数量配额。

## 5 完整备份与恢复

### 本机完整包（native）

1. 在“备份恢复”点“创建完整备份”。选择全部已保存环境，或从环境页带来的明确 ID；**全部不是当前一页，所选范围不会因搜索或翻页扩大**。选工作区以外的新 `.prismbackup` 文件；取消系统选择器不受理任务。
2. 勾选允许正常关闭范围内会话，点“正常关闭并导出”。无法确认停止时中止，不自动强杀。查看结果或“导出任务”；离开页面、返回或 Escape 只关闭结果窗口，不等于取消已受理任务。
3. 等到“完整备份已发布”，保留文件和 SHA-256。“结果待保存 / 核实”不是确认完成，临时 `.partial` 不是完成包。“已发布备份”只列服务记录，手动核实终态后刷新列表。包包含网站数据，请妥善保管；诊断不需要附上备份。
4. 点“导入完整备份”→“选择本机备份包”→“完整校验并预览”。“恢复前只读预检”分为影响环境、精确内核、代理凭据三栏；此时不停止环境、不提交数据库或替换目录。取消/丢弃只释放预览，不恢复数据。
5. 缺失精确内核或身份冲突时先解决，再重新预检；不生成新 seed 绕过冲突。点“下一步：确认恢复”，分别确认覆盖、凭据重输与正常停止，再点“确认并完整恢复”。备份不包含内核二进制。恢复保留原 ID、seed 与设备参数，只处理包内环境；包外环境保留，已停止会话不自动重开。
6. “已回滚”表示恢复未完成、旧状态保留；“维护保护中”表示目录与配置尚未核对完成，不能启动或修改。沿原任务“重试核对/收尾原恢复”，不删锁、不手工换目录。取消进行中恢复是明确取消原任务并请求回滚，不保证已关闭会话重开。
7. 受理结果未知时使用“继续核实原导出/原恢复”，只重发原 requestId、原包摘要、原输出和原授权，不另选输出或新建破坏性操作。查看旧记录不会消费原请求。

历史桌面证据：五个主切点及回滚再中断已实际 Kill 自有 helper 验证，真实三存储恢复/重开有证据；权限/空间不足等未实测条件不据此宣称通过。本轮页面合成结果不扩展这些事实。

代理密文只面向原 Windows 用户；不承诺跨用户、跨机器可解密。仅备份一个环境也可能涉及共享代理引用，预检结果为准。

### 网页演示 JSON（demo，不能导入本机）

“创建快照”只保存当前浏览器里的演示配置；“导入快照文件”只读解析 `prism-prototype / schemaVersion 1` JSON，10 MB 是解析保护、不是环境数量配额。完整包与诊断 JSON 会被拒绝。

校验通过后先显示“演示快照恢复预览”，再单独确认替换全部演示配置。存在模拟运行/启动/停止中的环境时禁止恢复；写入失败保留原工作区与确认窗口，可修复存储后重试。恢复保持原 seed，重置停止状态并清空代理密码/旧检查，不操作真实目录；快照历史与活动记录不会被导入文件覆盖。演示快照可能含示例 Cookie，请勿放入真实 Cookie。

HTTP/SOCKS5到上游的认证不加密；HTTPS代理才有TLS。SOCKS5 UDP ASSOCIATE/BIND及明文HTTP Upgrade未支持并拒绝。WSS、DNS、IPv6、WebRTC及UDP/QUIC独立出口尚未验收；不能把启动参数当无泄漏保证。底层Windows隔离服务自身损坏不在首版已保证范围。

## 6 回收区与内核升级

移除环境先进入回收区，原身份和数据引用保留。找回恢复原环境；永久删除需要明确确认，部分删除失败按原任务收敛，不能视为可完整找回。

内核页的默认构建只影响后续新草稿。已有环境升级需明确选择一个已停止环境：查看差异 → 完整备份 → 在工作副本上先旧后新试用 → 正常停止副本 → 明确切换。失败或取消保留原状态。旧内核不能直接打开已升级目录；需要退回时使用迁移记录中的升级前完整备份。代理副本使用正式隔离和前检；合成存储试用通过私有管道供页，只验证该受控条件，不代表所有网站兼容或外部出口验收。

## 7 出问题时导出脱敏诊断

1. 在“操作记录”点击“生成诊断预览”。若数据库无法打开，可直接在“工作区需要处理”对话框中生成最小报告。
2. 窗口只展示安全字段摘要，不回显原始 JSON。查看字段后点击“保存这份诊断 JSON”，选择工作区外的新文件。服务不覆盖已有文件；取消保存不会写出文件。
3. 保存回执 SHA-256 与预览一致才显示已保存。连接中断时点“核实原导出”；离开页面后返回仍保留原请求。
4. 若原文件被移动或存储盘不可读，核实可能无法结束。可以明确“结束此次核实”，保留旧文件可能已发布的事实，再生成新报告。应用会话内保留旧请求回执；应用重启后不自动重放任何导出，请自行核对原位置。

报告白名单仅含版本、构建摘要、已保存状态、错误码、计数与维护标志，不包含名字、备注、路径、主机名、代理地址、IP、凭据、Cookie、浏览数据、ID、seed、命令行或原始日志。最多列出最近 100 条任务、100 条会话和 20 个内核；工作区繁忙/损坏可返回最小或部分报告。它不会启动内核、检测网络、刷新未落盘状态或上传文件。签名字段为“本次未检查”，实际签名查看对应构建的发布记录。

“操作记录”可按对象/操作文字和结果筛选，点“详情”查看准确错误码与下一步。历史记录不是会话控制权；核对/强制结束入口必须匹配当前仍受控的准确会话，且仍受维护与占用保护。网页 demo 的“导出记录”是演示 JSON，不是真实原始日志；native 使用脱敏诊断入口。

“使用说明”保留本机使用指南、产品需求 PRD、开发与验收、内核适配合同四份内嵌文档。“下载文档”保存当前 Markdown；切换文档及文档内跳转会回到正文顶部。左侧功能入口回到现有环境、代理、内核、备份、记录页面，不增加云账号或配额入口。

常见处理：

| 提示 | 下一步 |
| --- | --- |
| `NETWORK_PROTECTION_UNAVAILABLE` | 本次会话隔离核对未通过；查看诊断，保留原环境，不改直连绕过 |
| `KERNEL_MISSING` / `KERNEL_INTEGRITY_FAILED` | 核对并安装所需精确构建，不随意换版本 |
| `PROCESS_STOP_TIMEOUT` / `SESSION_IDENTITY_UNCONFIRMED` | 先核对原会话；目录保护期间不手工替换 |
| `STORAGE_WRITE_FAILED` / `DISK_FULL` | 检查空间、权限；核实原操作，保留原数据 |
| `*_RESULT_UNCONFIRMED` | 核实原请求/任务，不按“未执行”另建破坏性操作 |
