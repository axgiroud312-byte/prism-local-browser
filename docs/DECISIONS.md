## D002 · T01 渐进契约与原型格式兼容（2026-09-30）

- 问题：旧页面在 React effect 中持久化，创建/编辑先提示成功；一次重写六页或改变快照格式会扩大本票范围并破坏旧演示记录。
- 证据：旧 `App.tsx` 保存后直接 notify，effect 稍后才写 localStorage；Issue #2 允许其他页通过渐进兼容层保留。
- 选择：注入 ApplicationService；创建/编辑/取消走公开预览和提交接口；DemoAdapter 集中管理存储，持久写入成功才发布状态。其他旧页通过仅 demo 可用的兼容接口更新。原型 `State` 和 `prism-prototype` schemaVersion 1 不改；localStorage 额外 `_application` 命名空间保存 revision，旧记录默认 revision 1，快照不输出该元数据。
- 理由：保持六页体验和已有快照，与 native 数据模型显式隔离，同时让服务层而不是页面裁定成功、冲突和失败。
- 影响：T01 原型与下一票 adapter 接入。Demo 预览、requestId 去重、Operation 与事件序号在当前服务会话有效，不宣称跨进程事务或持久任务恢复；持久 native 幂等与任务恢复在对应服务票实施。`accepted` 仅代表开始处理，只有逐块存储成功计入 completedIds。旧页也改为先持久写入再发布，失败不改变旧数据。

## D003 · T02 原生底座与未安装内核（2026-09-30）

- 问题：T02 必须能保存和重开初始环境，但精确内核安装和持久批量任务分别在 T04/T13，不能用旧演示内核和模拟任务冒充 native。
- 证据：Issue #3 要求 SQLite、必要引用、固定初始 seed 且未安装内核明确未就绪；T01 原型快照与演示基线没有真实二进制证据。
- 选择：Go/Wails 与纯 Go SQLite 驱动，固定版本；native 从空数据库初始化，与 localStorage 完全分开。仅缺失的 `kernel-pending` 引用作为尚未完成配置的占位，状态 missing、不允许启动、无实际版本/哈希声明。精确内核安装后新建引用具体 ID，旧占位环境须用户显式编辑绑定，不自动迁移或换 seed。T02 单条创建、编辑及查询通过原生契约；尚未接入功能明确 unsupported，不运行 demo 兼容入口。
- 理由：交付可用的持久底座并保持真实能力边界，不把尚未实现的后续票提前标为完成。
- 影响：T02 数据初始化与 UI 模式标记；SQLite 保存 revision 与成功请求去重结果，事务提交前失败不发布成功。初始模板字段是应用冻结输入，不代表指纹已在内核生效；T05 补完整生成能力与修订历史。

## D004 · T04 精确构建与不可变证据（2026-09-30）

- 问题：150说明链接存在但资产/Release/tag仍404；UA可伪装，路径校验与后续使用之间可能被替换。
- 证据：本票明确选148.0.7778.215，实际归档摘要与官方一致，PE/CDP与HTTP/网页身份实测一致；只读评审与真实junction/文件占用样本确认检查间隙的风险。
- 选择：官方精确tag+预期摘要，或系统选择器token+明确可信确认的本地ZIP；RPC不接受任意路径/URL/参数。固定实际暂存/诊断目录、归档和可执行清单，执行前后实算，完成诊断后发布新UUID；schema2不可UPDATE证据，不自动改变已有引用。CDP只走限定继承句柄的匿名pipe，保留沙箱与受控Job清理。
- 理由：将可信来源、实际字节和真实身份绑定，不用文件名、README或单一UA冒充精确版本。
- 影响：T04安装/能力与T05/T06使用合同；148不是生产推荐，其他版本不自动继承148能力。取消或清理失败不会撤销已经确认的完整性失败；复验未完成也不误判健康字节损坏。

- 问题：共享桌面的UIA验证有焦点/输入干扰，用户明确要求不要再测试自动化点击。
- 选择：停止后续自动点击与用户桌面操作；自动CI仅后台检查、构建和无头真实内核读值。原测试不删除，点击只在用户明确重新要求时启用，CI手动开关默认false。

- 影响：后续票不再自动点界面；需要新增真实页面证明时准确保留待验收，不将无点击后台结果冒称新页面验证。

## D006 · 档案历史与能力编译分离（2026-09-30 / 2026-10-01）

- 问题：当前seed唯一约束不允许通过复制当前档案行记录历史；元数据编辑与设备变化共用修订会误判身份变化。上游参数存在不等于本项目已验收。
- 选择：schema3在稳定fingerprint引用下追加不可变档案历史，回滚生成新单调修订；环境revision与档案configRevision独立。迁移保留旧seed/生成器/pending。规范化摘要覆盖服务生成的固定输入/精确内核/能力版本，提交检查原预览基线与当前修订。
- 理由：回滚同一身份不用破坏活动seed约束；普通名称/代理不重生成。Generate只改预览，不顺带启动探测；编译器只消费选定构建的已核验能力，不混入假GPU/字体/屏幕或未经核验的菜单语言。
- 影响：同内核回滚不替换数据引用；host-only忙租约交T06监督器接入。真实样本仅用临时诊断profile，不推导真实Cookie/正常启停；跨内核迁移仍属T20。
