# 开发规范

本规范用于领取、实现、评审和验收开发任务。当前任务范围见 [执行规则](GOAL.md) 与对应 issue，产品行为查 PRD，接口与持久化查 DEVELOPMENT，真实内核能力查 KERNEL 合同和实际证据。发现不一致时先核对当前用户要求与源码事实，再在同一任务中修正文档，不把过时描述变成额外审批步骤。

2026-10-07 用户明确采用 Ant-Browser 式共享内核、独立数据和逐环境代理，取消额外 AppContainer/共享 ACL/每会话内核副本。新代理保持明确绑定、前检、失败报错及不自动直连；不再承诺 OS 全路径强制隔离。下文 T11/D017 的历史系统隔离结果保留来源，不作为要求恢复旧方案的依据；新范围见 [KERNEL 启动合同](KERNEL.md#环境与代理的启动顺序)。

## 1 当前基础与交付层级

当前仓库保留 React/TypeScript 独立交互原型。领域规则在 `src/domain.ts`，页面和旧模拟任务在 `src/App.tsx`；T01 已提取应用契约与 DemoAdapter，创建编辑经注入契约，localStorage 由 DemoAdapter 管理。T02 的 WailsAdapter、Go/Wails 壳与 SQLite 配置服务、T03 用户级安装预览、T04精确内核安装与隔离诊断已验收；现有实际入口应以源码为准。

T05–T21的服务实现现均已接入，T11正式隔离、T14 FIFO与T20代理副本共用保护链；本机受控实跑及无点击集中检查见[首版验收报告](verification/V1-final.md)。独立远端、人工UI与干净Windows仍待验，远程CI的实际结果及范围分别记录，候选包不等于正式交付。待验收票保持OPEN、不计完成；首版支持前提经用户明确调整，见[D017](DECISIONS.md#d017--首版以正常-windows-网络隔离为支持前提2026-10-05)。

每个任务选择以下交付层级，并按其所需证据验收：

| 层级         | 完成证据                                                 |
| ------------ | -------------------------------------------------------- |
| 设计/文档    | 规则、接口、错误与验收可检查，引用一致。                 |
| 前端原型     | 页面可操作，模拟标记明确，演示数据与领域测试一致。       |
| 本地服务实现 | 实际服务代码及测试存在，持久化和失败路径有证据。         |
| 真实桌面验证 | Windows 上的进程、目录、内核读值、网络或恢复结果已核对。 |

构建成功、参数已传入、进程已创建、截图可见分别是局部证据，不互相替代。用户数据始终以示例或脱敏形式进入公开材料。

## 2 GitHub 任务与依赖

任务源为 [prism-local-browser Issues](https://github.com/axgiroud312-byte/prism-local-browser/issues)。开发 issue 写明关联需求 ID、当前行为、目标、范围外事项、blocking 依赖和可检查验收项。相关参考链接不自动构成 blocking 依赖。

- `spec` 是规范或总设计入口，需要拆成明确实现任务；不以完成一张 spec 代替实现验收。
- `ready-for-agent` 只表示任务说明足够清楚，不表示没有阻塞、不表示已完成，也不授予额外权限。
- 领取前核对每项 blocking 依赖已完成且其成果可用。依赖仅以“关闭”收尾但取消了交付时，仍视为未满足。
- 依赖未完成时记录具体缺口，推进不依赖它的工作或其他可领取任务；不绕过依赖制造重复实现。
- 人工新建任务默认只标记 `enhancement` 或 `bug`，整理清楚后才标记 `ready-for-agent`。
- 开始工作前检查关联 PR、已有承担者和工作区，避免同一文件被并行覆盖；PR 用关联 issue 追踪结果。

任务完成要满足自身验收项，并说明实际执行的检查；任务标签和“代码已提交”都不单独代表业务完成。完成本次指派的范围，不自动接续历史 T01–T21 任务队列。已有用户授权范围内持续实施，不增加常规操作确认流程。

## 3 前端和应用服务

提取适配层时先定义稳定的请求、响应与错误结构，再把现有演示行为接到 DemoAdapter；同一页面通过注入 adapter 接入 native 服务。保持原型可以单独运行。

页面负责输入、状态展示和交互，不直接拼接浏览器命令、访问任意磁盘路径或修改真实 Cookie 数据库。服务按内部 ID 解析内核、目录和凭据，并重新验证输入。

演示返回标记 `mode: demo`，真实服务返回标记 `mode: native`。native 服务拒绝演示预览及演示快照；没有真实观测时不填假 `observedFingerprint`。源码推导标记 `source-derived`，实际采样标记 `observed` 并附时间及会话。

新业务副作用进入服务层，纯解析和校验保留为独立函数。按实际修改拆分组件和模块，不为移动文件而重写无关页面。

## 4 数据、身份和异步任务

- 当前原型快照是 `prism-prototype`、schemaVersion 1；`coreId`、`ready` 等现存字段不能无迁移地改成未来模型。桌面备份使用独立且明确的格式，不冒充原型 JSON。
- seed 首次保存后固定。查询、打开详情、启动、关闭和修改代理不重生成；重新生成先改预览，保存时再提交修订。克隆新建 ID/seed/空数据，恢复保留原身份。
- 应用保存自己可控制的输入和版本；内核支持能力决定参数，不独立随机拼接互相矛盾的硬件字段。种子不同不等于所有输出都不同。
- native 修改使用事务、外键、requestId 幂等与 expectedRevision 检查。持久提交成功后才发布成功；失败保留原数据和可定位错误。
- 当前 localStorage 只作为演示存储，DemoAdapter 写入成功后才发布新状态。坏数据保留原文供找回；跨标签页冲突阻断旧写入。不得把这些保护宣称为数据库跨进程事务。
- 长任务用 operationId 区分受理、进度、取消和完成；事件使用单调序号，迟到事件不能回退终态。取消只影响对应任务，准确保留和报告已完成条目。
- 调度器限制昂贵启动工作的同时进行数量；资源错误明确返回。调度并发不是产品允许保存或保持运行的实例配额。
- Cookie 解析与真实写入分离，保留合法空值、session、到期时间和分区等语义；真实写入后读取核对，按实际成功/失败条目报告。

## 5 凭据、进程和文件边界

以下要求在相应 native 能力引入时实施，不能仅添加文案便标为完成：

- 凭据使用受保护的本机存储并以引用访问；密码、Cookie 值和完整调试端点不进入普通响应、日志、命令行或公开材料。测试使用可识别的假值验证脱敏。
- 环境 ID 与规范化数据目录共同参与独占保护；检查最终路径在应用数据根内，拒绝路径穿越和重解析点越界。维护、删除和恢复先取得对应锁。
- 判断进程身份结合 PID、创建时间和会话；陈旧锁核对实际进程，不仅按锁文件年龄判断。只停止目标环境的受控进程树。
- 以参数数组启动已核验的可执行文件，保留浏览器沙箱。运行中不替换目录、删除环境或提交新指纹。
- 代理身份、认证与网络出口分别验证；故障保留代理策略、明确报错并禁止应用自动切直连。启动前检查不等于运行期断线保护，不将浏览器代理参数扩大成 OS 全路径隔离；实际流量证据按当前 KERNEL 合同验收。
- CDP 默认关闭；需要时使用受限本地通道。loopback 不等于调用方已经认证，调试地址仅在必要的内部通道传递。
- SQLite 与文件目录替换使用维护锁、暂存、持久操作日志和回滚实现可恢复一致性。完整恢复失败不能报告总体成功。
- 升级先备份完整用户目录及配置，用工作副本验证；旧内核不得直接打开已被新内核升级的目录。跨机器登录状态恢复单独验证。

## 6 检查与证据

日常检查与默认 CI 只运行浏览器自动化点击测试：`npm run check` 等同 `npm run test:ui`。Playwright 使用独立 5183 端口启动 Vite，直接检查当前源码，无需先构建。CI 使用单个 Node.js 24 Windows 任务，安装 npm 依赖和 Playwright Chromium 后执行页面测试。

现有页面测试覆盖独立 demo 和模拟 Wails bridge。通过只表示这些页面交互及模拟响应通过，不能证明真实 Chromium 启动、代理出口、数据隔离或 Windows 安装已验收。

其他检查保留为按需工具，命令以 `package.json` 为准：

| 情况 | 按需检查 |
| --- | --- |
| 纯文档修改 | 核对相关链接；需要自动核对时运行 `check:docs`。 |
| 类型、领域、解析、存储或异步行为变化 | 运行相关类型或模块测试，检查实际改变的行为与失败恢复。 |
| native 能力变化 | 检查对应模块；声称真实能力生效时补进程、目录或网络证据。 |
| 明确验证打包或发布 | 执行相应构建、安装或桌面验证，不作为普通 UI 修改的前置。 |

浏览器点击测试使用合成数据。Windows UI Automation、真实安装、内核探针和系统级实验不属于默认 CI；当前浏览器测试授权不扩展到这些操作。简单文案或样式调整不机械增加测试，已有检查失败则定位并修复相关原因。

issue/PR 记录命令、实际结果与未验证项。报告与失败附件位于 `output/playwright/`。`docs/ACCEPTANCE.md` 保留原验收日期和范围，新增结果不把历史未验收能力改写为已完成。

## 7 公开仓库与许可

公开提交只包含项目代码、文档、合成样本和已检查的证据。真实代理凭据、账号 Cookie、用户目录、内核安装包和本机私人路径留在版本库外；截图和错误附件也检查这些内容。

固定内核保存来源、版本、架构、哈希和能力记录。本项目原创 MIT 不覆盖所有 Chromium 组件；引入依赖或分发内核时更新第三方声明并保留其适用许可证。

旧商业材料和 Ant-Browser 只作为现有文档描述的参考，不复制未明确授权的代码与资源。本规范不改变已授权任务的执行范围，也不添加云服务、人员权限或额外发布流程。
