# T14 阶段4：共用保护链的启动队列

2026-10-05；[Issue #15](https://github.com/axgiroud312-byte/prism-local-browser/issues/15)。原blocking T07/T11仍未正式关闭；按用户指派及六阶段计划消费已验证的本机生命周期/隔离成果，不把外部网络验收视为通过。

## 已实现和局部验证

- 启动票据按持久受理顺序FIFO；只串行昂贵启动，不限制已运行环境数。每项仍走原Runtime.Start及实际ProtectedProxy，不新建旁路启动器。
- 取消等待项仅移除自己的票据；普通关闭使排队项失效。界面显示等待数量、取消排队启动及仅重试资源已释放的失败项。
- 每项保留operation/session/request身份，重复请求不多启动；启动重开沿用已有核对而不重放旧队列。
- 服务测试实跑通过：A启动阻塞时取消B，C资源失败，D继续；A/D可同时保持运行，仅C重试。取消在最终就绪发布前已受理时，不允许迟到成功覆盖取消，并清理返回的进程。
- [真实应用证据](T11-production-application-observations.json)新增两个代理Cookie用途环境通过FIFO和正式隔离同时保持运行；Cookie写后核对、空值/session/HttpOnly/persistent/Secure及A/B独立通过。

## 同阶段迁移

[双版本代理迁移证据](T20-protected-observations.json)：真实148和150分别安装验证，通过正式资源owner、前检和全树身份。试用的合成存储页仅由固定CDP tab/URL的私有管道提供，无代理绕过；标记`private-pipe-canary`，不伪造最终HTTP Accept-Language或外部出口观测。实际站点读写仍经受控上游。

选择试用→切换失败回滚→再次试用并成功切换→新构建读回旧数据→写入新数据→升级前完整备份恢复→管理器重开，均通过；原seed及未选环境不变。

## 限制

本机受控资源实测不替代远端无旁路、人工UI、其他Windows/内核组合或安装包验收；没有自动点击。T14/T20不据此关闭issue或增加正式验收计数。集中回归留阶段5。
