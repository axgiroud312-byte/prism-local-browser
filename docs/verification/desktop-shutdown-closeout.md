本记录属于用户明确要求的桌面可用性修复；用户已取消严格 1:1 对齐要求。历史退出记录与失败证据保留。本轮子任务只执行源码检查与定向自动化，没有启动桌面程序或真实内核，不能据此增加正式桌面通过计数。

## 问题与修复

原入口在 `OnShutdown` 和 defer 中忽略 `Service.Close` 错误；清理超时、原预检暂存占用或结果待保存时仍可能返回退出码 0。服务原先还会在结果未保存时关闭数据库，随后再次 Close 无法重试保存。

- Windows Wails 2.16.0 的 `OnBeforeClose` 返回 true 可以保留窗口。新退出协调器异步执行一次关闭，重复关窗共享该次处理。成功后才调用 Quit 放行，窗口消息循环不等待清理。
- 从首次关窗开始，桌面入口与服务均拒绝新业务。暂留窗口不会重新开放已停止的服务。
- 资源或 worker 未结束：保留原归属，提示继续原清理。原预检暂存无法删除：保留内部原来源与准确暂存，提示释放占用后重试。提示只包含固定中文说明，不包含原始错误或路径。
- 观测待保存：保留数据库，仅重试原观测保存，不重复浏览器启动、Cookie 写入或目录操作。保存和原暂存清理均确认后才关库。
- 原受理仍待核实：关闭重试复用恢复、回收或迁移的原 receipt/journal 核实入口。确定未受理时精确解除该 task；确定已落盘时保留维护状态并提供明确的非 0 退出重开；仍未知时保留原请求与数据库。各 worker 入口拒绝关闭状态，核实不会在原 workers.Wait 之后添加 worker 或启动目录动作。独立审查发现的初版卡死问题已修复，不把单纯的“保留窗口”当成有效重试。
- 资源已结束但原恢复、回收或迁移仍保护：保持原持久维护语义，明确允许用户保留数据与日志退出重开。该退出返回非 0，不报告原任务成功。
- 存储关闭调用自身失败：保留首次错误，提供明确的非 0 退出重开路径。Go 1.27.1 `sql.DB.Close` 在驱动关闭前已标记 closed，第二次调用直接返回 nil；本机 `NetworkStore.Close` 同样消费原句柄。因此没有把第二次 nil 当成底层关闭重试或清理通过。
- 没有走正常关窗的 fallback 也核对关闭结果；错误显示安全提示并返回非 0。正常已确认关闭复用成功结果，明确未完成退出复用原错误。
